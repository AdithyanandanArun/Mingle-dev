Mingle 0.0.3 fixes Git repository detection on Windows.

## Fixes

- Uses Git-compatible null-device paths consistently for cloning, repository inspection, shared-project joining and untracked diffs. Node’s raw Windows device path could make Git reject its configuration and misidentify a valid checkout.
- Shared-project joining now distinguishes an inspection/configuration failure, an ownership trust issue and a bare repository from a folder that is genuinely not a Git repository.
- Adds native Windows regressions and packaged-runtime checks for fresh clones, Unicode and space-containing paths, linked worktrees, nonrepository folders and the invitation join account boundary. Checks use disposable repositories and do not invoke providers or accept real invitations.

The compatibility choice is supported by [Git for Windows’ null-device regression report](https://github.com/git-for-windows/git/issues/6449). Git environment isolation, hook restrictions and repository ownership checks remain enabled.

## Downloads

- **Windows:** run `mingle-0.0.3-win32-x64-setup.exe` to upgrade the affected installation. The per-user installer is unsigned.
- **Debian/Ubuntu:** `sudo apt install ./mingle_0.0.3_amd64.deb`.
- **Other Linux:** extract `mingle-0.0.3-linux-x64.tar.gz`. Its Chromium sandbox helper must be root-owned with mode 4755.

All assets have SHA-256 sidecars. Provider tools and accounts are installed separately. Upgrading preserves existing Mingle user data; this fix does not require recloning an intact repository.
