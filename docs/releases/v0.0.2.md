Mingle 0.0.2 for Linux x64 and Windows x64.

## Downloads

- **Debian/Ubuntu:** `sudo apt install ./mingle_0.0.2_amd64.deb`.
- **Windows:** run `mingle-0.0.2-win32-x64-setup.exe`. Installation is per-user; the installer is unsigned.
- **Other Linux:** extract `mingle-0.0.2-linux-x64.tar.gz` and run its `mingle` executable. The Chromium sandbox helper must be root-owned with mode 4755.

Each download includes a SHA-256 sidecar. Packages contain Electron, Node, the web UI and local server. Provider tools and their accounts remain separate. Upgrading preserves the existing user-data directory.

## Fixes

- Joined teammates open the shared group conversation, including existing joined profiles without an explicit local-agent preference. Deliberate individual-agent selections remain available.
- Member conversations show shared routing, assignments, task and result metadata in chronological order. Stable message identities suppress duplicate mirrors while retaining distinct messages with the same text.
- Remote artifact handoffs transfer committed work before publication, validate assignment scope across the full history, support verified inputs to later remote assignments and stop interrupted unpublished transfers.
- Completed work and owner-signed replies recover across restarts without rerunning providers. Replayed completion notifications reuse the original reply identity.
- Host-authorized run-state updates reach member devices. Existing stuck pending messages repair during history sync without another agent run.
- Delayed agent publications cannot undo a newer withdrawal; idle delivery handling and presence reporting are more reliable.

## Verification and limits

The assembled source passed 392 server tests, five web tests, TypeScript checks, a production web build and browser acceptance. Shared-browser checks used two separate Linux profiles with real accounts and cloud mailbox delivery; the existing stuck member message repaired with unchanged provider run counts and exactly one reply on each account. See [the verification report](../team-session-fix-verification-20261026.md).

Native release workflows separately check Linux and Windows packaging and installer behavior before publication. Physical multi-computer/network operation and Windows hardware are outside the recorded manual acceptance. If the host device is offline, new team work cannot be scheduled. Windows signing, automatic updates and public AUR distribution remain unavailable.
