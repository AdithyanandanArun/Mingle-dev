# Account level provider usage and earned resets

Settings → Usage reads Codex and Claude account limits without requiring a coding session. `GET /api/providers/:provider/usage` accepts only `codex` and `claude`; `?refresh=true` asks for a refresh subject to the existing 15 second minimum refresh interval. Account snapshots are process memory only, cache for at most 60 seconds, and concurrent reads coalesce. A read uses a neutral temporary working directory and never inserts projects or sessions, reads transcripts, sends a prompt, or consumes a reset.

Codex reads `account/read` with `refreshToken: false` and `account/rateLimits/read` over a short lived app-server connection. The native reset token is an opaque five minute in-memory lease bound to the Codex executable setting, resolved installation path/version and a SHA-256 digest of the native account identity. Account IDs are preferred; if the native protocol only supplies email and account type, those are conservatively bound together. Raw account identity and credentials are neither returned nor logged. A missing stable identity disables reset actions. Settings refresh invalidates leases and fences reads already in progress from minting a stale lease.

`POST /api/providers/:provider/usage/reset` requires the strict `{idempotencyKey,snapshotToken,creditId?}` body and represents an explicit user action. Before the first consume request, Mingle confirms the leased account, re-reads current reset grants, and validates a selected grant as an unexpired `codexRateLimits` grant with `status: available`. A known grant list must contain at least one eligible grant; the native available count is used only when grant details are unknown and no specific grant was selected. Mingle ignores client supplied availability. The native consume receives the same caller UUID on retries. A retry must reuse the UUID, snapshot token and selection; uncertain results are never reported as a confirmed outcome. Process memory retains the original account/installation binding for a bounded uncertain attempt so its exact request can be resolved after the five minute lease expires. A service restart loses that ledger and therefore fails closed with a stale-snapshot response; it never starts a replacement action automatically. HTTP 409 identifies stale authorization or changed selection, HTTP 501 identifies unsupported native redemption, and generic transport or unrecognized responses return 502. Only the four recognized native consume outcomes are returned as outcomes. A confirmed result triggers an independent fresh limits read; if that read fails, the confirmed outcome is returned with a null snapshot and a notice. Windows are never synthesized from the action result.

Claude's SDK exposes usage windows through its experimental metadata control but no reset redemption API. Mingle therefore reports Claude reset mode as `external`, with the fixed destination `https://claude.ai/settings/usage`; it does not scrape Claude's private web application, inspect credential files, or claim that Claude Code can redeem earned resets.

Provider protocol references checked for this implementation: [OpenAI Codex App Server](https://learn.chatgpt.com/docs/app-server) (`account/rateLimits/read`, `account/rateLimitResetCredit/consume`); [Claude usage reset help](https://support.claude.com/en/articles/17007452-what-is-a-limit-reset). The installed Claude SDK's `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET` exposes reported limits only. Future native response or SDK changes remain unsupported until their wire shapes are verified.
