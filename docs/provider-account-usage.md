# Account level provider usage and earned resets

Settings → Usage reads Codex and Claude account limits without requiring a coding session. `GET /api/providers/:provider/usage` accepts only `codex` and `claude`; `?refresh=true` asks for a refresh subject to the existing 15 second minimum refresh interval. Account snapshots are process memory only, cache for at most 60 seconds, and concurrent reads coalesce. A read uses a neutral temporary working directory and never inserts projects or sessions, reads transcripts, sends a prompt, or consumes a reset.

Codex reads `account/read` with `refreshToken: false` and `account/rateLimits/read` over a short lived app-server connection. The native reset token is an opaque five minute in-memory lease bound to the Codex executable setting, resolved installation path/version and a SHA-256 digest of the native account identity. Account IDs are preferred; if the native protocol only supplies email and account type, those are conservatively bound together. Raw account identity and credentials are neither returned nor logged. A missing stable identity disables reset actions. Settings refresh invalidates leases.

`POST /api/providers/:provider/usage/reset` requires the strict `{idempotencyKey,snapshotToken,creditId?}` body and represents an explicit user action. Before the first consume request, Mingle confirms the leased account, re-reads current reset grants, validates a selected grant as available and unexpired, and uses the native available count only when details are unknown and no specific grant was selected. Mingle ignores client supplied availability. The native consume receives the same caller UUID on safe retries. A retry must reuse the UUID and selection; uncertain results are not automatically retried or reported as success. One in-flight consume per idempotency key is fenced in process memory. A confirmed result triggers an independent fresh limits read; if that read fails, the confirmed outcome is returned with a null snapshot and a notice. Windows are never synthesized from the action result.

Claude's SDK exposes usage windows through its experimental metadata control but no reset redemption API. Mingle therefore reports Claude reset mode as `external`, with the fixed destination `https://claude.ai/settings/usage`; it does not scrape Claude's private web application, inspect credential files, or claim that Claude Code can redeem earned resets.

Provider protocol references checked for this implementation: [OpenAI Codex App Server](https://learn.chatgpt.com/docs/app-server) (`account/rateLimits/read`, `account/rateLimitResetCredit/consume`); [Claude usage reset help](https://support.claude.com/en/articles/17007452-what-is-a-limit-reset). The installed Claude SDK's `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET` exposes reported limits only. Future native response or SDK changes remain unsupported until their wire shapes are verified.
